### Q-001 使わないプロバイダのシークレットもダミーで作らせるか、宣言側を可変にするか

- 発生: 2026-09-06 / #249（課金の秘密を Secret Manager へ移す）のレビュー対応中
- 種別: 依存 / 外部サービス連携
- 状況: `defineSecret()` で宣言した秘密はデプロイ時に Secret Manager 側で解決され、
  存在しないと**非対話デプロイ（CI）がその場で落ちる**（firebase-tools の
  `deploy/functions/params.js` の `ensureSecret`。実装を読んで確認済み）。
  いまは `BILLING_SECRETS` が 3 つを無条件に宣言しているため、
  `architecture.md` が「どちらか一方だけ使える」と書いている構成
  （Stripe だけ / IAP だけ）でも 3 つ作る必要がある。
  暫定として「使わない側はダミー値で作る」を `billing.md` に書いて塞いである。
- 選択肢:
  - A) このまま（ダミー値で作る）— 推奨。設定の増える箇所がゼロで、
    ダミーの空文字なら配線は無効のまま動く。手順が 1 行増えるだけ
  - B) `BILLING_PROVIDERS`（非秘密の env、既定は両方）を足し、
    使うプロバイダの分だけ宣言する — ダミーは要らなくなるが、
    設定のノブが 1 つ増え、既定のままだと結局 3 つ必要なので
    「知らないと踏む」点は変わらない
  - C) プロバイダごとに関数を分ける（`api` を Stripe 用 / RevenueCat 用に割る）—
    宣言は最小になるが、エンドポイントの URL 構成とデプロイ単位が変わる
- ブロック: 無し（A で塞いであるので実装は進められる）。B / C を選ぶなら
  `apps/functions/src/lib/billing.ts` と `api.ts`、`use-env.sh`、`billing.md` を直す
- 進めた範囲: A の前提で `billing.md` の手順・チェックリストと
  `billing.ts` のコメントに「3 つとも作る」を明記した
