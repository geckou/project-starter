## 回答済み

### Q-001 使わないプロバイダのシークレットもダミーで作らせるか、宣言側を可変にするか

- 回答: 2026-09-06 / **A（このまま。使わない側はダミー値で作る）を採用**
- 判断の理由:
  - B（`BILLING_PROVIDERS` を足す）は既定を「両方」にする限り、結局 3 つ作らないと
    デプロイが落ちる。既定を変えれば今度は課金が黙って 503 になる。
    「知らないと踏む」点が変わらないのに、設定のノブだけ増える
  - C（プロバイダごとに関数を分ける）はエンドポイントの URL 構成とデプロイ単位が変わる。
    直す対象（秘密の置き場）に対して影響範囲が大きすぎる
  - A は追加の設定がゼロで、踏んだときのエラーが firebase-tools 側から
    「どの秘密が無いか」を名指しで出る。手順を 1 行増やすだけで足りる
- 反映済み:
  - `.claude/docs/billing.md` 1-2 節に手順（`printf '' | firebase functions:secrets:set X --data-file -`）
  - 同ファイルの完了チェックリストに「使わないプロバイダの分もダミー値で作った」
  - `apps/functions/src/lib/billing.ts` の `BILLING_SECRETS` にも同じ注意
- 再考の目安: 「片方だけ使う」構成が実際に増えて、ダミー作成の漏れが繰り返し起きるようなら B を入れる
