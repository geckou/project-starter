# wrap-up

セッションの終わりに、次のセッションが即座に再開できる状態を作る。

## 手順

### 1. 完了条件の確認

このセッションで「完了」にした機能があれば、Definition of Done（CLAUDE.md）を満たしているか確認する:

- [ ] `yarn type-check` / `yarn lint` / `yarn test` が通る
- [ ] 差分のセルフレビューを通した（`/review`）
- [ ] テスト方針の必須ケースがある
- [ ] spec.md が実装と一致している
- [ ] 新しいドメイン用語を planning.md の用語集に追記した
- [ ] roadmap.md の機能ステータス表を更新した

満たしていない項目があれば、このセッション内で対応するか「実装中」に戻す。

### 2. ロードマップの引き継ぎ追記

`.claude/docs/roadmap.md` を更新する:

1. 「現在の進捗サマリ」を最新状態に**上書き**する（最終更新日・ブランチ・全体状況）
2. 「セッション引き継ぎ」の先頭にテンプレートで追記する:
   - このセッションでやったこと（PR 番号があれば記載）
   - 次セッションのタスク（チェックリスト）
3. **ローテーション**: 引き継ぎが 5 件を超えたら、古いものを `.claude/docs/roadmap-archive.md` へ移動する（ファイルがなければ作成する）

### 3. 確認事項の提示

`.claude/docs/questions.md` の「未回答」を確認する。このセッションで積んだ項目があれば、
**終了する前にユーザーへまとめて提示する**（詳細な出し方は `/questions`）。

- **これが決まらないと進まない作業**を添える。次のセッションで何から動けるかが決まるため
- ユーザーがその場で答えたら反映してから終わる。答えないなら未回答のまま残す（急かさない）

### 4. メモリ記録

このセッションでユーザーから受けたフィードバック・気づいたパターンがあれば、`memory/evolution.md` のプロトコルに従って記録する:

- 既存の `memory/short-term/`・`memory/long-term/` に同じ趣旨があれば `pain_count` を +1
- 新規なら `memory/short-term/` にファイルを作成
- 昇格条件（pain_count >= 2 / >= 3）に達していれば昇格処理を行い、ユーザーに通知する

### 5. コミットと PR

未コミットの変更を整理してコミットし、**push して PR を出す**
（CLAUDE.md「PR は出す、マージは人が決める」。マージはしない）:

- 作業内容ごとに分割し、`<type>: <description>` 形式のメッセージを付ける
- ドキュメント更新（roadmap.md 等）も忘れずに含める
- push する前に `/review` でセルフレビューを通し、出た指摘を処理する
- push して PR を作る。PR タイトルもコミットメッセージ規約に従う
- PR 本文に「何を確認してほしいか」と、対応する spec.md のセクションを書く。
  未回答の確認事項でブロックされている部分があればそれも書く
- 作業が途中で PR にできない場合のみ、ブランチへの push だけ行い、その旨を報告する

### 6. 終了報告

最後に以下を簡潔に報告する:

- このセッションの成果（完了した機能・進んだ作業）と、**出した PR**
- 次セッションの最初のタスク
- 未解決の問題・ユーザーに判断してほしいこと（未回答の確認事項の件数）
