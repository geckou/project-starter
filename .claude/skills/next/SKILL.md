# next

CLAUDE.md の「次何をすればいい？」の手順を実行する。

## 手順

0. `.claude/docs/questions.md` の「回答済み」に、**保留のまま再開されていない作業**がないか見る。
   あればそれを最優先で提案する（前提が解けている＝すぐ進められる作業のため）
1. `.claude/docs/roadmap.md` の**機能ステータス表**を読み、現在のバージョンの「未着手」の機能を列挙する
2. **フェーズ順**（1_基盤 → 2_バックエンド → 3_フロントエンド → 4_結合）で最も早いフェーズのものに絞る
3. その中で**前提機能が全て「完了」**のものに絞る（依存が解消されていない機能は選ばない）
4. 優先度 **「必須」→「重要」→「任意」** の順、同率なら他の機能から依存されている数が多い順に1つ選ぶ
5. 機能ステータス表の「関連仕様」に列挙された `spec.md` のセクション（画面・データモデル・API）を読む
6. Figma リンクがあればデザインを確認する
7. 以下を宣言し、**そのまま着手する**（承認待ちで止まらない。CLAUDE.md「自律性の境界」）:
   - 選んだ機能と選定理由（フェーズ・優先度・依存関係）
   - 作業内容と影響範囲（作成・変更するファイル）
   - 使うスキル（/new-collection, /new-function, /new-page 等）
   - 完了条件（Definition of Done）

## 候補がない場合

- 「未着手」がない → 「実装中」の機能の残作業を確認して提案する
- 前提機能が未完了のものしかない → ブロックしている前提機能を先に提案する
- 現在のバージョンが全て「完了」 → 次バージョンの計画（planning.md のコア機能一覧から機能ステータス表への転記）を提案する

## 注意

- **着手前に止まるのは次の場合だけ**（それ以外は宣言して着手する）:
  - 選んだ作業が「自律性の境界」の **4. その場で止めて聞く** に触れる（デプロイ・本番操作・外部への送信）
  - 候補が同点で並び、どれを選ぶかで以降の作業順が大きく変わる（このときも推奨を1つ示して聞く）
- 着手したら、機能ステータス表の該当機能を「実装中」に更新してから実装を始める
- 実装中に判断が必要になっても止まらない。`.claude/docs/questions.md` に積んで進める（`/questions` で回収する）
