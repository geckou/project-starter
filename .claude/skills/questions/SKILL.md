# questions

`.claude/docs/questions.md` に積んだ確認事項を、**ユーザーが短時間で答えられる形**に整えて提示し、
出た回答を実装・仕様書・キューへ反映する。

作業中に確認が必要になっても止まらずキューへ積むのが原則（CLAUDE.md「自律性の境界」）。
このスキルはその回収側にあたる。

## 手順

### 1. 未回答を読む

`.claude/docs/questions.md` の「未回答」セクションを読む。1件もなければ「確認事項はありません」と伝えて終わる。

### 2. 答えやすい順に並べ替えて提示する

順序は「**止まっている作業が多いもの** → 影響範囲が大きいもの → 細部」。
1件あたり次の4点だけを、この順で短く出す。**長い調査ログをここに貼らない**（詳細はファイルにある）。

1. 問い（1行）
2. 選択肢と**推奨案**（推奨には理由を1行）
3. これが決まらないと進まない作業
4. 保留の手前までに済ませたこと（あれば）

選択肢が2〜4個に収まるものは `AskUserQuestion` で選択式にする。
自由記述が要るもの（命名・文言・数値）はテキストで聞く。

### 3. 回答を反映する

回答ごとに、以下を**その場で**行う。持ち帰らない。

- **回答が出た** → キューの項目を「回答済み」へ移し、`回答` と `反映` を記入する
- **保留していた作業** → 前提が解けたので着手する（大きい場合はロードマップの残タスクへ積んでから着手順を提案する）
- **回答が複数の項目を解く** → まとめて移す。前提が連鎖している場合は、解けた順に着手する

仕様に関わる回答は、**実装より先に** `.claude/docs/spec.md` に反映する（仕様書ファースト）。
新しいドメイン用語が出たら `.claude/docs/planning.md` の用語集に追記する。

### 4. キューを更新する

- 回答済みの項目を「回答済み」セクションの**先頭**へ移し、`回答` と `反映` を記入する
- 「未回答」が空になったら `（なし）` に戻す
- 回答の結果として**新しい確認事項**が出たら、その場で「未回答」に積む（聞き返しでセッションを往復させない）

### 5. 報告する

- 反映した内容（実装を直した項目・仕様書へ反映した項目）
- 再開した保留作業
- まだ未回答で残っている項目（ユーザーが答えを保留した場合）

## 注意

- **答えを急かさない。** ユーザーが「後で」と言った項目は未回答のまま残し、その作業も保留のままにする
- 1回の提示で**5件を超えるなら、ブロックしているものだけに絞る**。全部並べると読まれない
- 未回答が残っていても、他に進められる作業があればそちらへ戻る。回答を待って止まらない
